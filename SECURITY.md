# Security

Every third-party skill or plugin in this harness, copied or linked, went through the `third-party-install-guard` review before it was added: fetched without running, scanned for risky patterns, checked with an antivirus pass, and every file that runs on its own (hooks, install scripts, agent instructions) read by hand.

A verdict covers the version listed, on the date listed. Newer versions are not covered until reviewed again. The companion plugins in `.claude-plugin/marketplace.json` are pinned to these exact commits, so enabling them installs the reviewed code.

## What the harness itself runs

- `hooks/session-start` (Claude Code only): reads `ROUTING.md` from this repository and prints it with the plugin's folder path. No network, no writes.
- `hooks/install-gate` (Claude Code only, before each shell command): if the command installs or runs third-party code, it makes Claude Code ask you first and reminds the agent to run the `third-party-install-guard` review. It never blocks or runs anything. No network, no writes, no other program started. When it cannot tell, it asks.
  - **Asked about:** package installs with a package named (`npm`/`pnpm`/`yarn`/`bun` `install`, `i`, `add`, `create`, `init <pkg>`, `yarn global add`, `yarn workspace <name> add`, `dlx`, `npm exec`; `pip`, `python -m pip`, `uv add`, `uv tool install|run`, `uv run --with`, `pipx`, `poetry`/`pdm`/`rye`/`bundle` `add`, `conda`/`mamba` `install`; `cargo install|add|binstall`, `go install|get`, `go run <module>@<version>`, `gem install`, `composer require`, `deno add|install <pkg>`, `dotnet add package`, `dotnet tool install`, `nix profile install`, `nix-env -i`, `Install-Module`); system packages (`brew`, `winget`, `choco`, `scoop`, `apt`, `apt-get`, `dnf`, `yum`, `zypper`, `pacman -S`/`yay -S`/`paru -S` with any options, `apk add`, `snap`, `flatpak`, `port`); `npx`, `pnpx`, `bunx`, `bun x`, `uvx`; `claude plugin install`, `claude plugin marketplace add`, `claude mcp add`; `code --install-extension` (and Cursor, Windsurf, VSCodium); `gh extension install`; `docker run` / `podman run`.
  - **Also asked about: remote code run straight away.** `curl … | sh` and `wget -qO- … | bash`, with `sudo -E`, `doas`, `env`, `NAME=value`, `busybox`, a path such as `/bin/bash`, `bash -s --`, more pipes between, `|&`, a quoted URL with `&` or `;` in it, a pipe at the end of a line, and `python`, `node`, `perl`, `ruby`, `php` reading a script from stdin (`| python3 -`, `| python3 - --version 1.8.0`); `sh -c`, `eval`, `ruby -e`, `python3 -c`, `node -e` with `"$(curl …)"`; `bash <(curl …)`, `source <(curl …)`; `base64 -d | sh`; `bash <<< "$(curl …)"`, `python3 <(curl …)`, `… > >(bash)`; `| exec bash`, `| nohup bash`, `| csh`; `git -c alias.x='!npm install …'`; `iwr … | iex`, `iex (irm …)`, `iex "& { $(irm …) }"`, `iex ((New-Object Net.WebClient).DownloadString(…))`, `[scriptblock]::Create((irm …))`. **Downloaded, then run in the same command line:** `curl -o x.sh … && sh x.sh`, `curl … > i.sh && bash i.sh`, `curl … | tar xz && ./install.sh`, `wget … && bash i.sh`, `./install.sh` or `python3 get-pip.py` after a download, `irm … -OutFile i.ps1; .\i.ps1`, and `git clone` or `gh repo clone … && cd … && npm install` / `make` / `./install.sh`.
  - **Where it looks:** options may come before the verb (`npm --prefix app install x`, `apt-get -y install x`, `pip --quiet install x`); the program may have a path (`/usr/bin/npm`, `venv/bin/pip`, `npm.cmd`) or quotes (`"npm" install x`, `python3 -m "pip" install x`); it is found after `sudo`, `&&`, `;`, `|`, a line break, a backslash line continuation, a bracket, `$( )` or inside `bash -c "…"`. A no-break space counts as a space.
  - **Not asked about:** installs of an existing lockfile (`npm ci`, `npm install` with no package, also with `--prefix app` or `npm -w <workspace>`, `pnpm install --frozen-lockfile`, `yarn install`, `deno install`, `npm init -y`); `npx` of a tool already in the project's `node_modules/.bin`, without a version; downloads that only save or read data (`curl -o file` with nothing run after it, `curl … | jq`, `curl … | python3 -m json.tool`, `x=$(curl …)`). **Text is not skipped:** install words ask wherever they sit, also in a commit or PR message (`git commit -m "docs: pip install note"`), an `echo`/`printf` argument or a `grep` pattern. An earlier version let such quoted text through; three audit rounds kept finding commands hidden behind that rule, so it was removed. A pattern argument such as `grep -E "curl .* \| sh" file` is read by the same rules as any command, so it may or may not ask; nothing in a command is skipped because it is quoted. An escaped pipe (`\|`) counts as a pipe, because in PowerShell a backslash escapes nothing. Anything else is matched, so a false ask is more likely than a miss.
  - **Size:** a run stays well under the hook's 5-second timeout, on Linux, macOS (bash 3.2) and Git Bash. The gate asks without matching when the hook input is over 40,000 characters, the command is over 20,000 characters or has 600 or more escapes (line breaks, quotes) as sent, or is over 4,000 characters once decoded (a line break counts as 3, so a heredoc of roughly 100–200 lines asks). A word over 400 characters is cut to its first and last 200 before matching; if its unread middle holds a `;`, `|`, `&`, `$(` or a backtick, the gate asks.
  - **Not matched at all:** a command hidden from plain reading (built from variables, `${IFS}`, brace expansion or `printf`, decoded with anything but `base64 -d | sh`, `xargs`, an alias, a function); a download and its run in two separate commands; a script the agent writes and then runs, even in the same command (`echo … > run.sh; sh run.sh`); `npm install` / `make` in a folder cloned in an earlier command; other tools than the shell; package managers and verbs not listed above (`npm update`, `npm link`, `choco upgrade`, `conda create … <pkgs>`, `man`-style text outside quotes). The scanner reads one logical line (up to 20 continued lines) at a time and has no download-then-run rule; the gate has one. The gate raises the bar; it is not a wall (see below).
  - **Off:** on in every scope, `MAKKOV_HARNESS_SCOPE=design` included. Off with `MAKKOV_HARNESS_INSTALL_GATE=off`; use it for headless runs (`claude -p`, CI), where an "ask" has nobody to answer it, once the commands in that run were reviewed. Its test cases are in `hooks/install-corpus.json`, which the scanner's tests read as well.
- `install/` scripts: copy files from this repository into the agent's folders. No downloads.
- `cloud/setup-design-tools.sh` (optional, Claude cloud environments only): installs ffmpeg from Ubuntu and two pinned npm packages with `--ignore-scripts` and `--before` the review date, so their dependencies resolve only to versions published by then. Runs only if you paste it into your environment's Setup script, or when you say yes to the agent's offer in a cloud session.
- `.github/workflows/upstream-watch.yml` (GitHub only, weekly): reads the upstream repositories of the pinned companions through the GitHub API and updates one issue in this repository. It cannot change a pin or any file.
- `skills/design-score/` (the Design Score bundle, `mh-score.js`): runs in the page you score, inside your browser. It measures the page and shows the result in a panel of its own (one element, removed when you close it). The bundle itself makes no network requests, keeps no storage and never changes the page's own content. When an agent loads it from GitHub Pages, the script tag carries the bundle's SRI hash (sha384, checked in CI against the built file), so the browser runs only the bundle this release ships and refuses anything else. Its optional Node runner (`scripts/score.mjs`) drives a Chrome you already have through a puppeteer-core you already have, and installs nothing.
- The Design Score bookmarklets ([score.html](https://makkov-design.github.io/makkov-harness/score.html)): the loader makes one request, to this repository's GitHub Pages, for `score/mh-score.js` (the latest version) as it is published there at that moment, loads nothing else and removes its script tag once the bundle has loaded. It is not pinned to a version: the `?v=` in its address only refreshes caches. Every version also stays published, unchanged, at `score/<version>/mh-score.js`; that is the copy an agent loads, with its SRI hash. The request is sent with no referrer, so GitHub sees it like any visit (your IP address) but not the address of the page you score. Nothing the page contains and nothing Design Score measures is sent. The offline bookmarklet and the console snippet carry the whole bundle, make no request and run exactly the code you saved.
- No skill here sends data anywhere unless the user asks for a task that needs it.
- Telemetry, in one place: the routing map, the installers and Design Score send none. The bundled `media-use` (copied from HeyGen's hyperframes skills) can send coarse usage events to PostHog, linked to your HeyGen account when you are signed in; in this harness that is off unless you set `MEDIA_USE_TELEMETRY=1`. The Hyperframes CLI sends its own usage events by default; when the harness's video skills start it, they set `HYPERFRAMES_NO_TELEMETRY=1` unless you set `MEDIA_USE_TELEMETRY=1`. When you run it yourself, or through the cloud setup script, set `HYPERFRAMES_NO_TELEMETRY=1`. Impeccable, an optional companion, has telemetry on by default (`impeccable telemetry off`).

The website is not part of what you install. It counts page views with GoatCounter (no cookies, no personal data, a pinned script checked with Subresource Integrity) and loads its fonts from Fontshare and Google Fonts, which see your IP address like any font request; the Design Score bundle and the bookmarklets never load it. The same verdicts, searchable and with what each piece runs, sends and needs, are on the [security index](https://makkov-design.github.io/makkov-harness/security.html).

## What the install guard is, and what it is not

The `third-party-install-guard` skill is a review procedure for the agent: pin down exactly what is being installed, fetch it without running it, scan it, read every hook and install script by hand, give a Green, Yellow or Red verdict, and install only the reviewed version, pinned. In Claude Code, `hooks/install-gate` adds a technical step: a command that installs or runs third-party code turns into a question to you, with a reminder to run the review.

What it does not do:

- It is not a sandbox. Code that you approve runs with your permissions, like any install.
- It cannot see code that a package downloads later, at run time; the review says so when it finds such downloads, and rates them Yellow at best.
- The scanner is a tripwire, not a verdict: it misses anything clever, and its findings are read by hand.
- In other agents (Codex, Cursor, Gemini CLI and the rest) the skill is instructions only; there is no hook there. Keep each tool's own approval prompt for shell commands on.
- The gate matches common install commands. A determined or compromised agent can still find another way; it raises the bar, it is not a wall.

For more assurance: keep shell commands on "ask" in your agent's permission settings, install per project rather than globally, and run agents that install things for you in a container or a virtual machine.
